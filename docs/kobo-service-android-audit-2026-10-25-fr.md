## 3. Contre-qualification et limites

- **Aucune importation directe** : APK Android 2.3, JNI binaire `armeabi` sans source identifié, service permanent et pilotes spécifiques. Les permissions `su` et démarrage automatique sont incompatibles avec un PMKB frugal et à la demande.
- **Risques dans le driver Android** : `MXCFB_SET_UPDATE_MODE` recopie une valeur utilisateur dans `giEINK_UPDATE_MODE` **sans borne 0–3 visible** dans le handler ; `GET` écrit `ret = 0` après `put_user`, pouvant masquer une erreur. Les chemins EPDC/tramage doivent être revus pour allocations, limites, cache, consommation et waveform. Aucune correction de sécurité revendiquée.
- **Risques pour l'écran** : le tramage Atkinson est destiné au **Y1 binaire**, ce n'est **pas** un remplacement général de nos visuels 16 gris. Des modes DU rapides peuvent dégrader le rendu/augmenter le ghosting selon les contenus et waveforms.
- **Récupération inchangée** : aucune écriture dans la microSD, U-Boot, PRE-P1, P1, P2, P3, HWCONFIG ou waveform. Aucune preuve que cette branche Android fournisse notre FIRST BOOT Linux sans Nickel.

## 4. Suite utile pour PMKB

1. **R1/R3 et PMKB-UI** : spécifier quatre **profils de rendu** indépendants d'un `ioctl` particulier, puis tests sur buffers synthétiques 1440×1080 (zones partielles, inversions, permutations, ghosting non simulable). Vérifier la correspondance sur le vrai noyau PMKB avant de rendre ces profils accessibles.
2. **Tactile** : compléter nos tests de rotation `0°,90°,180°,270°` à partir des équations de ce noyau, avec bornes et `SYN` fiables ; ne pas importer le handler `EV_LED` détourné.
3. **Performance** : comparer les deux noyaux Marek (**1 vs 4** buffers), et le coût d'un Atkinson Y8→Y1 sur l'hôte puis sur la cible. **Aucun patch kernel ni activité de store maintenant**, le FIRST BOOT physique reste prioritaire.
4. **UX future** : possible menu « Écran / rotation / USB » pour PMKB, mais en **PMKB-UI natif**, sans Android ni service permanent ; mode stockage seulement après contrat d'accès exclusif.

**Bilan de qualification** : code Java/service, manifeste, ressources, diffs historiques, symboles ioctl du noyau Android, EPDC/tramage/ZForce et HWCONFIG PMKB **lus** ; **compatibilité du protocole appli↔noyau Android corroborée par sources**. **0 téléchargement de firmware ou source complète, 0 code intégré, 0 compilation, 0 essai sur Aura HD, 0 modification du système ou de P2.** Toute compatibilité **E606C0 matérielle reste NON QUALIFIÉE**.
