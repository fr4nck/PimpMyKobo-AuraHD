# PMKB — HA-IPaper, forks et concept Store « Maison »

**Audit du 25 octobre 2026 : lecture statique du code public, sans installation, compilation ni test sur Kobo.** Source principale : [o0Zz/ha-ipaper](https://github.com/o0Zz/ha-ipaper), branche `main` au commit `a681d2e0239ff9fd40285017c4d3a3bc31e86dfe` du **20 octobre 2026** ; licence **MIT**. Application Python 3.11+, FastAPI/Jinja2, Home Assistant, HTML et CSS pour **anciens navigateurs Kobo/Kindle**. Elle n'est ni un firmware Kobo ni un pilote EPDC. Une [présentation par l'auteur à la communauté Home Assistant (18 janvier 2026)](https://community.home-assistant.io/t/ha-ipaper-dashboard-for-epaper-kobo-kindel/976427) mentionne le réemploi d'anciennes liseuses ; un commentaire du **7 juin 2026** rapporte un essai positif sur **Kobo Glo**, pas sur Aura HD E606C0.

**Verdict : P2 / IDÉE D'APPLICATION `Maison`, future entrée `*.pmkb` du Store PMKB.** Conserver les fonctions et l'ergonomie, **pas son runtime navigateur/serveur sur notre Aura HD**. Notre système est Linux autonome sans Nickel, 512 Mio RAM, écran 1080×1440 et KOReader v2026.07.1 ; le FIRST BOOT scellé reste prioritaire.

### Défauts et risques statiques vérifiés dans le code historique

- La méthode `HomeAssistantService.get_data()` suppose que **`weather.home` existe** et peut répondre à `weather.get_forecasts` ; une absence ou une erreur de météo provoque une exception **avant** le rendu de toutes les pages. [`pages.py`](https://github.com/o0Zz/ha-ipaper/blob/main/src/ha_ipaper/routers/pages.py) affiche alors `error_message` et `stacktrace` à l'utilisateur, tout en renvoyant **HTTP 200**. **Retenir le comportement dégradé proposé par le fork rsaksida, pas ce couplage.**
- `HomeAssistantService.call_service()` attend ensuite le prochain événement `state_changed` (sans timeout défini dans le code examiné), même si le service appelé n'entraîne pas nécessairement un changement d'état ; un appel pourrait attendre indéfiniment. Ceci est un **risque de blocage statique**, pas un incident matériel reproduit.
- Le [manifest de l'add-on](https://github.com/o0Zz/ha-ipaper/blob/main/ha-ipaper-addon/config.yaml) expose **8081**, et son [DOCS.md](https://github.com/o0Zz/ha-ipaper/blob/main/ha-ipaper-addon/DOCS.md) avertit explicitement **« no login »** : tout client joignant l'interface peut envoyer des commandes HA. `config.yaml` du serveur lie par défaut à `0.0.0.0`. **Ne pas exposer ce service au WAN** ; si une passerelle PMKB est créée, authentification/pairage local simple et actions explicitement bornées.
- Aucun **mesurage du coût réseau, temps CPU, RAM, ghosting ou autonomie de notre Aura HD** n'a été réalisé. Un e-paper statique ne consomme pas comme son système Wi-Fi resté éveillé.

## 3. Proposition concrète pour le Store PMKB : `Maison`

**Format cible : application `Maison.pmkb` optionnelle, native PMKB-UI, sans installation de Python, Node, FastAPI ou navigateur sur la liseuse.** Home Assistant reste un **système extérieur facultatif** ; si aucun serveur n'est configuré, écran d'accueil `Non configuré` et aide, pas de réseau lancé automatiquement. Les actions reposent sur la [REST API officielle Home Assistant](https://developers.home-assistant.io/docs/api/rest/) : lecture sélective `GET /api/states/{entity_id}`, appels `POST /api/services/{domain}/{service}`. Une passerelle déployée du côté HA peut fournir un flux JSON compact et conserver les informations d'identification **hors Kobo**.

| Version | Fonctionnalités prévues et critères de recette |
| --- | --- |
| **M0 — hors ligne, simulateur** | Page `Maison` 1080×1440, interface **16 gris**, grandes cibles tactiles, cartes configurables : **Lumières**, **Chauffage**, **Volets**, **Température/Humidité**, **Météo**, **Scènes**. Simulateur alimenté par JSON synthétique, aucune dépendance HA ni code web tiers. Affichage `hors ligne / dernière mise à jour` explicite. Contrat `DOWN/MOVE/UP` de la HAL ; conserver un seul socle graphique. |
| **M1 — accès LAN sur demande** | Découverte/association locale explicite à Home Assistant, favoris d'entités, lectures **ciblées** et cache borné, appels de services Home Assistant avec délais, messages d'erreur/reprises, distinction `action demandée` / `état confirmé`. **La météo peut tomber en panne sans affecter les commandes.** Ne pas intégrer de mot de passe/jeton dans des fichiers publics ; stockage de configuration privé ou petite passerelle appairée. |
| **M2 — énergie e-ink** | Rafraîchir **uniquement les rectangles modifiés**, plein écran selon besoin de propreté ; intervalle configurable ou bouton Actualiser, éviter le meta-refresh fixe 60 s ; Wi-Fi **actif seulement à la demande** et suspension effective hors de l'app. Le mode « panneau mural permanent » serait distinct et **nécessiterait une mesure de batterie/consommation**. |
| **M3 — tableau libre** | Favoris et ordre des cartes, groupe par pièce (séjour, cuisine, etc.), grille à 4 colonnes ou selon dimensions, mises à jour ponctuelles et actions `scène` ; configuration persistée dans **les données applicatives P3**, sans modification de P1/P2. Les actions à effet sensible peuvent demander validation. |

**Invariants** : application optionnelle du Store et non composant de boot ; pas de dépendance à Nickel/Android ; conserver KOReader moderne comme lecteur ; pas de serveur HTTP local exposé par défaut ; pas de Wi-Fi forcé pendant le sommeil ; connexion externe testée puis retirée si l'application est fermée. **Le projet initial HA-IPaper ne devient pas le backend officiel de PMKB : c'est la référence fonctionnelle.**

**Tests préconisés** : validité des payloads d'entités et bornes sur chaque carte, 0/1/N entités découvertes, météo absente, HA injoignable, erreur 401/503, action n'entraînant aucun `state_changed`, rafraîchissement de carte seulement, traces tactiles E606C0, réveil/veille Wi-Fi, icônes en noir/blanc et charge mémoire. **Aucun PASS revendiqué sur une image ou un matériel PMKB actuel.**

## 4. Qualification et non-actions

- **PASS audit source** : parent GitHub MIT et branches, code FastAPI/API HA, six composants UI, modes Web/Supervisor, HTML 60 s, risque météo forcée et endpoint de commande sans login identifiés.
- **PASS comparaison Git** : **3 forks directs publiquement identifiés sur 4 annoncés**, `main` comparés, branche secondaire `rsaksida:kobo-lights` inspectée, 3 tests unitaires vus **sans exécution** ; 2 adaptations **hors réseau de forks** vérifiées.
- **NON QUALIFIÉ** : quatrième fork non visible, support E606C0 sans Nickel, consommation et taille du futur binaire PMKB, usabilité tactile et e-ink réelle, sûreté de l'hébergement HA du tiers.
- **0 installation, 0 téléchargement de code ou de dépendances, 0 exécution de service Web, 0 PASS matériel, 0 écriture sur les partitions ou modification de FIRST BOOT, 0 code tiers incorporé.**

**Priorité finale : P2 — retenir l'application `Maison` comme candidate au Store après FIRST BOOT, avec la règle P1 « panne météo isolée », et suivre les versions externes sans déplacer le cœur PMKB vers un navigateur.**
